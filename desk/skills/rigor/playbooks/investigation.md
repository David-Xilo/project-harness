# Investigation

**You own the answer. Plan, route, write.** An investigation is read-only. It produces a
cited explanation or a recommendation, not a change.

1. Route through the `desk:how` skill. For a question about motives, also through `desk:why`.
2. The throughput checkpoint is one line: `throughput checkpoint: n/a, read-only investigation`.
3. Write the `desk:how`-shaped answer (Overview, Key Concepts, How It Works, Where Things Live,
   Gotchas), or, for a choice between alternatives, a recommendation with a table of
   tradeoffs.
4. Run the reply through `desk:unslop`.

No commit and no `desk:architect`, unless the investigation leads to a change. Then hand back
to the user and route to Bug fix or Feature.

**Reply:** the answer. For "are we sure?", your real judgment with reasons, and push back
if the premise is wrong.
